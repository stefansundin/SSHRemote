## អំពី SSH Remote

ឯកសារបកប្រែនេះត្រូវបានបង្កើតដោយ AI ដោយប្រើ GitHub Copilot (GPT-5.3-Codex) ហើយអាចមានកំហុសក្នុងការបកប្រែខ្លះៗ។

SSH Remote គឺជាកម្មវិធីឥតគិតថ្លៃ និងបើកចំហប្រភពកូដ ដែលអនុញ្ញាតឱ្យអ្នកបញ្ជាកុំព្យូទ័រពីចម្ងាយដោយប្រើ SSH។

អ្នកអាចប្ដូរពាក្យបញ្ជាដែលត្រូវបានប្រតិបត្តិបានពេញលេញ ហើយមានការកំណត់ជាមុនសម្រាប់ការរៀបចំដែលពេញនិយម។

ខ្ញុំប្រើកម្មវិធីនេះដើម្បីបញ្ជាប្រព័ន្ធ HTPC របស់ខ្ញុំ ដែលកំពុងដំណើរការ Raspberry Pi OS។ ការបញ្ជា HTPC គឺជាសេណារីយ៉ូមូលដ្ឋានដែលកម្មវិធីនេះត្រូវបានបង្កើនប្រសិទ្ធភាពសម្រាប់វា។

កម្មវិធីនេះមិនមែនជាកម្មវិធីត្រាប់តាមស្ថានីយទេ ប៉ុន្តែវាអនុញ្ញាតឱ្យអ្នករត់ `apt-get install` បាននៅពេលមានស្ថានការណ៍បន្ទាន់។

## ចាប់ផ្តើម

ប្រសិនបើអ្នកចង់ប្រើសោ SSH ដើម្បីភ្ជាប់ សូមបើកការកំណត់កម្មវិធីជាមុនសិន ហើយនាំចូល ឬបង្កើតសោមួយ។

បន្ថែមម៉ាស៊ីនមេថ្មីដោយចុចប៊ូតុង `+` នៅផ្នែកខាងក្រោមស្តាំ។ បញ្ចូលព័ត៌មានលម្អិតសម្រាប់ការតភ្ជាប់ ហើយរក្សាទុក។

នៅពេលដែលអ្នកភ្ជាប់ជាលើកដំបូង អ្នកនឹងត្រូវបានស្នើឱ្យជ្រើសរើសការកំណត់ជាមុនមួយ។ ជម្រើសនេះកំណត់រចនាសម្ព័ន្ធប៊ូតុងឧបករណ៍បញ្ជាពីចម្ងាយឱ្យដំណើរការបានល្អលើកុំព្យូទ័រប្រភេទផ្សេងៗ។ សូមមើលខាងក្រោមសម្រាប់ការពិពណ៌នាអំពីការកំណត់ជាមុនដែលមាន។ ប្រសិនបើអ្នកចង់ អ្នកអាចចាប់ផ្តើមដោយគ្មានការកំណត់ណាមួយដោយជ្រើសរើស `No preset`។

ប្រសិនបើអ្នកមិនដឹងថាកុំព្យូទ័រ Linux របស់អ្នកកំពុងដំណើរការ X11 ឬ Wayland ទេ សូមរត់វានៅក្នុងស្ថានីយ៖

```shell
echo $XDG_SESSION_TYPE
```

វាគួរតែបង្ហាញ `x11` ឬ `wayland`។ អ្នកត្រូវរត់វានៅខាងក្នុងបរិស្ថានផ្ទៃតុ។

## ឧបករណ៍បញ្ជាពីចម្ងាយ

បន្ទាប់ពីបានភ្ជាប់រួច អ្នកអាចប្រើចំណុចប្រទាក់ឧបករណ៍បញ្ជាពីចម្ងាយដើម្បីផ្ញើពាក្យបញ្ជា។ ប្ដូរផ្ទាំងដើម្បីចូលប្រើវិធីសាស្ត្របញ្ចូលផ្សេងៗ។

ការចុចប៊ូតុងនីមួយៗនឹងប្រតិបត្តិពាក្យបញ្ជាមួយនៅលើម៉ាស៊ីនមេ។ វាមានការចំណាយច្រើនសម្រាប់អ្វីមួយសាមញ្ញដូចជាការចុចគ្រាប់ចុច ហើយអ្នកអាចមានការពន្យារពេលខ្ពស់មួយ បើប្រៀបធៀបនឹងក្តារចុចធម្មតា។ ខ្ញុំសង្ឃឹមថានឹងកែលម្អវានៅជំនាន់ក្រោយៗ។

ប្រើម៉ឺនុយដើម្បីចូលទៅក្នុងរបៀបកែសម្រួល។ បច្ចុប្បន្ន វាមិនអាចកែសម្រួលប្លង់ ឬរូបតំណាងប៊ូតុងបានទេ។ ខ្ញុំសង្ឃឹមថានឹងធ្វើឱ្យវាអាចធ្វើបាននៅជំនាន់ក្រោយ។

## ការកំណត់ជាមុន

អ្នកនឹងត្រូវដំឡើងឧបករណ៍ដែលត្រូវការសម្រាប់បរិស្ថានផ្ទៃតុរបស់អ្នក។

ខ្ញុំសូមណែនាំ `ydotool` ព្រោះតាមការសាកល្បងរបស់ខ្ញុំ វាមានប្រសិទ្ធភាពល្អបំផុត ហើយវាដំណើរការបានទាំងលើ X11 និង Wayland។

### ydotool

`ydotool` គួរតែដំណើរការជាមួយកម្មវិធីគ្រប់គ្រងបង្អួចណាមួយក៏បាន ប៉ុន្តែអ្នកត្រូវមានសេវាផ្ទៃខាងក្រោយមួយកំពុងដំណើរការ។ ប្រសិនបើការចែកចាយរបស់អ្នកផ្ដល់សេវា systemd សម្រាប់អ្នកប្រើ សូមចាប់ផ្តើមវាដោយរត់៖

```shell
systemctl start --user ydotool
```

ដើម្បីឱ្យសេវាចាប់ផ្តើមដោយស្វ័យប្រវត្តិនៅពេលចូលប្រើ សូមរត់៖

```shell
systemctl enable --user ydotool
```

សូមប្រាកដថាអ្នកកំពុងដំឡើង `ydotool` ជំនាន់ថ្មីគ្រប់គ្រាន់។ កំណែនៅលើ Ubuntu មុន 26.04 គឺចាស់ពេក។ សូមមើលខ្សែពិភាក្សាសម្រាប់ដំណោះស្រាយជំនួស។

សូមពិភាក្សាអំពី `ydotool` នៅក្នុងខ្សែពិភាក្សានេះ៖ <https://github.com/stefansundin/SSHRemote/discussions/5>

### xdotool

`xdotool` គឺសម្រាប់កុំព្យូទ័រដែលដំណើរការ X11។ X11 គឺជាប្រព័ន្ធដែលកុំព្យូទ័រ Linux ភាគច្រើនបានប្រើជាប្រវត្តិសាស្ត្រ ទោះបី Wayland កំពុងក្លាយជាពេញនិយមជាងមុនក៏ដោយ។

ចំណុចចម្លែកមួយរបស់ X11 គឺ អ្នកប្រហែលជាត្រូវអនុញ្ញាតការចូលប្រើទៅម៉ាស៊ីនមេ X។ នេះជាបញ្ហាប្រសិនបើអ្នកទទួលបានកំហុស "Authorization required"។ អ្នកមានជម្រើសមួយចំនួនដើម្បីដោះស្រាយបញ្ហានេះ ខាងក្រោមនេះជាជម្រើសពីរដែលបានដំណើរការល្អសម្រាប់ខ្ញុំ៖

ប្រសិនបើ `xauth list` មិនបង្ហាញធាតុណាមួយទេ សូមសាកល្បងបង្កើតឯកសារ `.Xauthority`៖

```shell
xauth generate :0 . trusted
```

ប្រសិនបើវាមិនដំណើរការ សូមសាកល្បងផ្តល់សិទ្ធិចូលប្រើដោយប្រើ `xhost`៖

```shell
xhost +local:$USER
```

អ្នកនឹងត្រូវរត់ពាក្យបញ្ជា `xhost` បន្ទាប់ពីបើកម៉ាស៊ីនម្តងៗ។ អ្នកអាចធ្វើឱ្យវាដំណើរការដោយស្វ័យប្រវត្តិដោយបង្កើតស្គ្រីប bash មួយ ហើយកំណត់ឱ្យវាចាប់ផ្តើមស្វ័យប្រវត្តិនៅពេលចូលប្រើ។

សូមពិភាក្សាអំពី `xdotool` នៅក្នុងខ្សែពិភាក្សានេះ៖ <https://github.com/stefansundin/SSHRemote/discussions/3>

### wtype

`wtype` គឺស្រដៀងនឹង `xdotool` ប៉ុន្តែសម្រាប់ Wayland។

ជាធម្មតា វាមិនគាំទ្រការបញ្ជាកណ្ដុរទេ ប៉ុន្តែខ្ញុំបានបង្កើតជំនាន់កែប្រែមួយដែលបន្ថែមការគាំទ្រកណ្ដុរ។ សូមដំឡើងវាប្រសិនបើអ្នកត្រូវការការគាំទ្រកណ្ដុរ៖ <https://github.com/stefansundin/wtype>

ប្រសិនបើអ្នកទទួលបានកំហុស `Compositor does not support the virtual keyboard protocol` នោះខ្ញុំសូមណែនាំឱ្យអ្នកសាកល្បងឧបករណ៍ផ្សេងទៀត ដូចជា `ydotool`។

សូមពិភាក្សាអំពី `wtype` នៅក្នុងខ្សែពិភាក្សានេះ៖ <https://github.com/stefansundin/SSHRemote/discussions/4>

### dotool

`dotool` គួរតែដំណើរការជាមួយកម្មវិធីគ្រប់គ្រងបង្អួចណាមួយ ដូចទៅនឹង `ydotool`។ តាមការសាកល្បងមានកម្រិតរបស់ខ្ញុំ វាយឺតជាង `ydotool` ច្រើន។

សូមពិភាក្សាអំពី `dotool` នៅក្នុងខ្សែពិភាក្សានេះ៖ <https://github.com/stefansundin/SSHRemote/discussions/6>

### cec-client

ការកំណត់ជាមុននេះស្ថិតនៅក្នុងដំណាក់កាលសាកល្បង ពីព្រោះខ្ញុំមិនទាន់អាចផ្ទៀងផ្ទាត់វាលើផ្នែករឹងរបស់ខ្ញុំបានទេ។ មតិយោបល់ត្រឡប់ត្រូវបានស្វាគមន៍។

សូមពិភាក្សាអំពី `cec-client` នៅក្នុងខ្សែពិភាក្សានេះ៖ <https://github.com/stefansundin/SSHRemote/discussions/7>

### macOS

មានការកំណត់ជាមុនមួយសម្រាប់បញ្ជា VLC លើ macOS ដោយប្រើពាក្យបញ្ជា AppleScript។ ខ្ញុំមិនបានដឹងអំពីឧបករណ៍ណាមួយដែលគាំទ្រការផ្ញើព្រឹត្តិការណ៍ក្តារចុច ឬកណ្ដុរទេ។

សូមពិភាក្សាអំពី macOS នៅក្នុងខ្សែពិភាក្សានេះ៖ <https://github.com/stefansundin/SSHRemote/discussions/8>

### Android

ប្រសិនបើឧបករណ៍ Android របស់អ្នកមានម៉ាស៊ីនមេ SSH ភ្ជាប់មកជាមួយ អ្នកប្រហែលជាអាចភ្ជាប់ទៅវា ហើយផ្ញើព្រឹត្តិការណ៍បញ្ចូលបាន។ វាមានលទ្ធភាពខ្ពស់ជាង ប្រសិនបើឧបករណ៍របស់អ្នកកំពុងដំណើរការ custom ROM ដូចជា KonstaKANG លើ Raspberry Pi។

សូមពិភាក្សាអំពី Android នៅក្នុងខ្សែពិភាក្សានេះ៖ <https://github.com/stefansundin/SSHRemote/discussions/9>

## ការគ្រប់គ្រងកម្រិតសម្លេងឆ្លាតវៃ

នៅពេលកែសម្រួលឧបករណ៍បញ្ជាពីចម្ងាយ អ្នកអាចរកឃើញការកំណត់គ្រប់គ្រងកម្រិតសម្លេង "ឆ្លាតវៃ" នៅក្នុងម៉ឺនុយ។ វាអាចបង្ហាញកម្រិតសម្លេងបច្ចុប្បន្នរបស់កុំព្យូទ័រនៅក្នុងកម្មវិធី ហើយអនុញ្ញាតឱ្យអ្នកកំណត់កម្រិតសម្លេងបានរហ័សដោយប្រើគ្រាប់រំកិល។ អ្នកក៏អាចប្រើប៊ូតុងផ្នែករឹងរបស់ឧបករណ៍អ្នក ដើម្បីផ្ញើពាក្យបញ្ជាបង្កើន/បន្ថយសម្លេងបានយ៉ាងរហ័ស។

ការអានកម្រិតសម្លេងបច្ចុប្បន្ន និងការកំណត់កម្រិតសម្លេងថ្មីដោយប្រើគ្រាប់រំកិល បច្ចុប្បន្នត្រូវបានកំណត់ជាក់លាក់ឱ្យប្រើ `pactl`។

កញ្ចប់ដែលមាន `pactl` ជាទូទៅត្រូវបានហៅថា `pulseaudio-utils` ឬ `libpulse`។

## សោ SSH

អ្នកអាចនាំចូល ឬបង្កើតសោ SSH នៅក្នុងការកំណត់កម្មវិធី។ ការភ្ជាប់ដោយប្រើសោ SSH មានសុវត្ថិភាពជាងការប្រើពាក្យសម្ងាត់។

វិធីងាយស្រួលបំផុតក្នុងការនាំចូលសោ SSH ដែលមានស្រាប់ពីកុំព្យូទ័រ គឺស្កេនកូដ QR មួយ។ អ្នកអាចប្រើកម្មវិធី `qrencode` ដើម្បីបង្កើតរូបភាពកូដ QR។ សូមរត់ពាក្យបញ្ជាដូចខាងក្រោម ដើម្បីបង្កើតកូដ QR៖

```shell
# ចូលទៅកាន់ថតសោ SSH របស់អ្នក៖
cd ~/.ssh

# បង្ហាញកូដ QR នៅក្នុងស្ថានីយ៖
qrencode -r id_ed25519 -t ansiutf8

# ជាជម្រើស អ្នកអាចបង្កើតឯកសាររូបភាព៖
qrencode -r id_ed25519 -o qr.png

# សោ RSA 4096-bit មានទំហំធំពេកសម្រាប់កូដ QR។ អ្នកអាចប្រើ gzip ដើម្បីឱ្យវាអាចដាក់ចូលបានប្រហែលៗ៖
cat id_rsa_4096 | gzip | base64 | qrencode -o qr.png
```

អ្នកអាចបញ្ជូនសោសាធារណៈទៅម៉ាស៊ីនមេដោយប្រើមុខងារ `បញ្ជូនសោសាធារណៈ` នៅក្នុងម៉ឺនុយ។ វានឹងបន្ថែមសោ SSH ដែលបានជ្រើសទៅក្នុងឯកសារ `~/.ssh/authorized_keys`។ វាជួយឱ្យអ្នកអាចផ្លាស់ប្តូរពីការចូលដោយប្រើពាក្យសម្ងាត់ ទៅការចូលដោយប្រើសោ SSH បានយ៉ាងងាយស្រួល។

អ្នកអាចនាំចូល និងប្រើសោ SSH ដែលបានអ៊ិនគ្រីប ប៉ុន្តែបច្ចុប្បន្នអ្នកមិនអាចបង្កើតសោប្រភេទនេះនៅក្នុងកម្មវិធីបានទេ។

## សុវត្ថិភាព

វាមិនអាចនាំចេញ ឬទាញយកផ្នែកឯកជននៃសោ SSH ឬពាក្យសម្ងាត់ដែលបានរក្សាទុក ចេញពីកម្មវិធីបានទេ។ ទិន្នន័យនេះត្រូវបានអ៊ិនគ្រីបដោយប្រើ AES 256-bit ហើយសោអ៊ិនគ្រីបត្រូវបានរក្សាទុកក្នុង Android Keystore។ ទិន្នន័យដែលបានអ៊ិនគ្រីបត្រូវបានដកចេញពីការបម្រុងទុក Android។

មិនមានកម្មវិធីរាយការណ៍ការគាំងនៅក្នុងកម្មវិធីនេះទេ។ មិនមាន telemetry ទេ។ មិនមានការផ្សាយពាណិជ្ជកម្មទេ។ មិនមានសំណើបណ្ដាញណាមួយឡើយ លើកលែងតែការតភ្ជាប់ SSH។

សុវត្ថិភាពរបស់កម្មវិធីនេះមិនទាន់ត្រូវបានអូឌីតទេ។ ប្រសិនបើអ្នកមានបទពិសោធន៍ក្នុងសុវត្ថិភាព Android ឬ SSH សូមមើលកូដប្រភព ហើយរាយការណ៍អ្វីដែលអ្នករកឃើញនៅក្នុង GitHub issue នេះ៖

<https://github.com/stefansundin/SSHRemote/issues/1>

## សំណើមុខងារ

សូមស្វាគមន៍ក្នុងការដាក់សំណើមុខងារ និងរបាយការណ៍កំហុសនៅក្នុងឃ្លាំង GitHub។ សូមប្រើភាសាអង់គ្លេស។ សូមរក្សាការបញ្ចេញមតិរបស់អ្នកឱ្យសុភាពរាបសា។ មតិយោបល់មិនគួរឱ្យគោរពនឹងត្រូវបានដកចេញ ហើយអ្នកប្រើអាចត្រូវបានរារាំងពីឃ្លាំង។

សូមពិនិត្យ issue និងខ្សែពិភាក្សាដែលមានស្រាប់ ដើម្បីមើលថាតើសំណួររបស់អ្នកត្រូវបានសួរ ឬឆ្លើយរួចហើយឬនៅ។

សូមមានការគោរព។ ខ្ញុំបានបង្កើតកម្មវិធីនេះក្នុងពេលទំនេររបស់ខ្ញុំ ហើយខ្ញុំកំពុងផ្តល់វាឱ្យដោយឥតគិតថ្លៃ។ ខ្ញុំកំពុងបង្កើតកម្មវិធីនេះសម្រាប់ការប្រើប្រាស់ផ្ទាល់ខ្លួនរបស់ខ្ញុំជាចម្បង។

សូមកុំផ្ញើអ៊ីមែលសួរសំណួរមកខ្ញុំ។ សូមព្យាយាមរក្សាការសន្ទនានៅលើ GitHub ព្រោះវាក៏ជួយមនុស្សផ្សេងទៀតផងដែរ! អ្នកអាចសួរសំណួរនៅក្នុងផ្នែក discussion លើ GitHub បាន។

អ្នកតែងតែត្រូវបានស្វាគមន៍ឱ្យ fork កម្មវិធីនេះដើម្បីអនុវត្តមុខងារផ្ទាល់ខ្លួនរបស់អ្នក។ នេះគឺជាវិធីដ៏ល្អមួយក្នុងការរៀន។ សូមពិចារណាចូលរួមចំណែកមុខងារដែលមានប្រយោជន៍។

កូដប្រភពត្រូវបានផ្ដល់អាជ្ញាបណ្ណក្រោម GNU GPLv3។ ប្រសិនបើអ្នកចែកចាយកំណែកែប្រែនៃកម្មវិធីនេះ នោះអ្នកក៏ត្រូវតែធ្វើឱ្យកូដប្រភពមានសម្រាប់អ្នកដទៃផងដែរ។
